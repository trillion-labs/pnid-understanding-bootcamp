# 12. 스킬을 추가하고 전후를 비교하는 실습

## 실습 목표

프롬프트 한 번을 잘 쓰는 것과, 반복되는 작업 방식을 스킬로 저장하는 것의 차이를 경험합니다.

스킬은 정답을 외우는 파일이 아닙니다. 다음처럼 여러 P&ID 질문에서 반복되는 판단 기준을 보존합니다.

- 파일명과 목록은 후보를 줄이는 자료이며 설비 요소가 존재한다는 증거는 아닙니다.
- 전체 구조용 이미지에서는 작은 태그를 억지로 읽지 않습니다.
- 질문 단서를 확인하는 데 필요한 구역만 부분 확대합니다.
- 이미지에서 본 문자열과 해석한 설비 요소를 분리합니다.
- 도면 선택 정답과 근거 정답을 따로 평가합니다.
- 확인하지 못한 질문 단서는 `unknown`으로 유지합니다.

## 만든 스킬

- 경로: `skills/pid-visual-evidence/`
- 진입점: `skills/pid-visual-evidence/SKILL.md`
- 출력 계약: `skills/pid-visual-evidence/references/output-contract.md`
- 검증 상태: `quick_validate.py` 통과

## 왜 스킬을 짧게 만들었는가

OpenAI 공식 지침은 간결한 프롬프트가 성능과 token 효율을 개선할 수 있으므로 중복 지침을 제거하고 대표 평가로 검증하라고 권장합니다. 스킬에는 P&ID 작업에서 실제 결정을 바꾸는 지침만 넣었습니다.

Anthropic 공식 지침은 이미지 작업에 부분 확대 도구 또는 에이전트 스킬을 제공하면 관련 영역을 크게 볼 수 있어 이미지 평가가 개선될 수 있다고 설명합니다. 동시에 불필요하게 많은 도구 지시와 과도하게 긴 프롬프트는 피하라고 안내합니다.

따라서 스킬은 `항상 네 구역으로 나누기`, `항상 OCR 사용하기`, `반드시 위치 상자 만들기`처럼 도구 사용을 고정하지 않습니다. 질문과 필요한 근거 수준에 따라 도구를 선택합니다.

## 스킬 사용 전후를 비교하는 방법

### 1. 스킬 없이 Feeder #C 질문 실행

새 세션에서 질문 원문만 실행하고 결과를 저장합니다.

### 2. 스킬을 읽습니다

`SKILL.md`에서 다음 내용을 찾습니다.

- 언제 이 스킬을 사용합니까?
- 무엇을 하지 않도록 정했습니까?
- 어느 단계에서 부분 확대 이미지를 만듭니까?
- 완료 전에 무엇을 확인합니까?

### 3. 스킬을 사용해 같은 Feeder #C 질문 실행

새 세션을 다시 시작합니다. 질문, 모델, 추론 설정과 시간 제한은 그대로 두고 스킬만 추가합니다.

### 4. 도면 선택과 근거를 따로 채점합니다

도면번호만 맞았는지, 설비 요소 근거까지 맞았는지 분리합니다.

### 5. 스킬을 한 줄만 개선합니다

실제 오류가 있었을 때만 수정합니다. 예를 들어 motor 태그를 Expansion Joint로 오인했다면 `E-MT/EM은 motor 근거로 검토합니다`라는 구분을 추가합니다. 일반적인 장문 지침을 더하지 않습니다.

## 직접 실행하기

실행 순서와 CSV는 `experiments/skill-ab/`에 있습니다.

- `run-matrix.csv`: 앞으로 실행할 8개 행
- `existing-q005-results.csv`: GS Agent 기존 run 6개 입력 완료
- `README.md`: 실행·채점 절차
- `scripts/score_skill_experiment.py`: 점수 자동 계산

## 결과 입력 원칙

- 실행 직후 usage와 경로를 기록합니다.
- token 필드가 제공되지 않으면 비워 둡니다.
- 모델 UI가 보여 준 값과 추정값을 섞지 않습니다.
- raw response와 trace를 보존합니다.
- 사람이 근거를 검토하기 전에 총점을 해석하지 않습니다.

## 학습 질문

3. 스킬이 설비 요소 오인을 줄였습니까?
4. 도구 호출과 token은 늘었습니까, 줄었습니까?
5. 추가 비용만큼 검증 가능한 결과가 늘었습니까?
6. 스킬의 어떤 한 줄이 실제 행동을 바꾸었습니까?
