# AI에게 도면 작업을 맡기는 방법

앞 단원까지는 사람이 전체 도면에서 위치를 찾고, 필요한 곳을 확대하고, 확인한 정보를 정리했습니다. 마지막 단원에서는 이 과정을 Claude Code나 Codex가 한 번에 수행할 수 있도록 업무 요청문으로 만듭니다.

## 질문 한 문장과 업무 요청은 무엇이 다른가요?

일반 질문은 이미지를 보고 답을 달라고 요청합니다. 업무 요청은 어떤 파일을 사용하고, 무엇을 확인하며, 결과를 어떤 형태로 남기고, 언제 완료했다고 판단할지까지 함께 정합니다.

| 구성요소 | 전달할 내용 | 이 실습의 예시 |
|---|---|---|
| 목표 | 무엇을 확인해야 하나요? | Reception Bin 2에서 Feeder #C 전동기까지 연결 확인 |
| 입력 | 어떤 파일을 사용하나요? | 전체 이미지와 Feeder #C 확대 이미지 |
| 판단 규칙 | 무엇을 구분하고 추측하지 않아야 하나요? | 이미지 표기와 해석을 구분하고 인접 태그를 섞지 않기 |
| 출력 | 결과를 어떻게 작성하나요? | 네 값, 연결 순서와 근거 위치 |
| 완료 조건 | 무엇을 다시 확인해야 끝나나요? | 네 기준값을 원본에서 각각 재확인 |

## 그대로 사용할 수 있는 요청문

```text
assets/overview/sample-pid-overview-1600.png에서 RECEPTION BIN 2의 위치를 찾고,
필요하면 assets/regions/feeder-c-area-long-edge-1600.png를 사용해 작은 글자를 확인해 주세요.

RECEPTION BIN 2의 A측 하부 출구에서 VIBRO FEEDER #C 전동기까지 선을 따라가며
다음 네 항목을 도면에 적힌 그대로 기록해 주세요.

1. Reception Bin 2 장비 태그
2. A측 하부 출구 밸브 번호
3. Vibro Feeder #C 장비 태그
4. 전동기 심벌 표기와 태그

각 값의 연결 순서와 원본 근거 위치를 함께 설명해 주세요.
오른쪽 Feeder의 태그를 섞지 말고, 읽히지 않는 값은 추측하지 마세요.
마지막에 네 값을 원본 이미지에서 다시 확인한 뒤 완료해 주세요.
```

## 에이전트가 수행할 작업 순서

```text
전체 도면에서 질문 구역을 찾습니다.
        ↓
관련 구역을 확대해 작은 태그를 읽습니다.
        ↓
연결선과 인접 태그를 다시 확인합니다.
        ↓
네 값과 근거 위치를 기록합니다.
        ↓
원본에서 최종 확인합니다.
```

과정 자체를 길게 설명하게 만드는 것이 목적은 아닙니다. 최종 결과에서 어떤 파일과 위치를 확인했는지 검토할 수 있으면 됩니다.

## 사람에게 확인을 요청해야 하는 경우

- 질문에 필요한 구역이 현재 이미지에 포함되지 않았습니다.
- 같은 태그가 두 가지 문자열로 읽힙니다.
- 확대 이미지 밖으로 연결선이 이어집니다.
- 범례만으로 심벌의 의미를 확정할 수 없습니다.
- 실제 운전·정비·안전 판단으로 질문 범위가 확장됩니다.

이 경우 빈칸을 임의로 채우지 않고 `확인하지 못함`으로 남기거나 추가 원본을 요청해야 합니다.
