# 첫 번째 실험: P&ID 한 장을 얼마나 깊게 읽을 수 있을까요?

앞 단원에서는 사람이 P&ID에서 Feeder #C를 찾고, 위쪽 장비와 아래쪽 연결을 따라가며, motor와 joint 근거를 구분하는 과정을 살펴보았습니다.

이번에는 같은 작업을 Claude Sonnet, Codex Luna, Codex Terra에 맡겨봅니다.

## 먼저 두 종류의 질문을 구분합니다

이 워크북을 만들 때 처음 사용한 현업 질문은 다음과 같습니다.

> 보일러 계통에서 Bottom Ash Vibro Feeder #C Outlet Expansion Joint Ash Leak과 관련된 P&ID를 찾아 주세요.

이 질문은 P&ID가 여러 장 있을 때 가장 관련 있는 도면을 고르는 `도면 검색 질문`입니다. 기술 데이터 파일에서는 기존 실행과 연결하기 위해 별도의 질문 ID를 사용하지만, 워크북 본문에서는 질문의 의미를 그대로 설명합니다.

도면 검색 질문은 다음 상황에 적합합니다.

```text
입력: 여러 P&ID 파일
출력: 가장 관련 있는 도면번호와 선택 근거
```

이번 실험에서는 `J-11520-ZM-105-005` 한 장을 이미 선택하여 이미지로 제공합니다. 그래서 질문의 초점을 도면 검색에서 단일 도면 이해로 바꾸었습니다.

> 이 P&ID에서 Vibro Feeder #C를 찾아 주세요. 장비 태그, 바로 위쪽에 연결된 장비, 아래쪽 출구 연결, Expansion Joint와 관련하여 이미지에서 확인되는 내용과 현재 이미지로 확인할 수 없는 내용을 설명해 주세요.

이 질문은 `단일 도면 이해 질문`입니다.

```text
입력: 선택된 P&ID 한 장 또는 그 일부
출력: 장비, 태그, 연결, 심벌과 확인하지 못한 내용
```

이 단원에서는 도면 검색 성능이 아니라, 한 장의 P&ID를 얼마나 정확하고 신중하게 읽는지 비교합니다.

## 이 실험에서 확인하려는 것

실험에서는 모델 순위보다 이미지 제공 방식과 확인 프롬프트가 답변에 미치는 영향을 확인합니다.

1. 같은 질문이라도 전체 도면과 부분 확대 이미지에서 답이 어떻게 달라집니까?
2. 같은 부분 확대 이미지라도 확인 순서를 제공하면 답이 어떻게 달라집니까?

첫 번째 비교는 이미지 제공 방식의 영향을 봅니다. 두 번째 비교는 프롬프트의 영향을 봅니다.

## 세 가지 실행 조건

### 조건 A: 전체 도면과 짧은 질문

전체 제목란, 범례와 반복 구조가 모두 보이는 이미지를 제공합니다.

```text
이 P&ID에서 Vibro Feeder #C를 찾아 주세요.

장비 태그, 바로 위쪽에 연결된 장비, 아래쪽 출구 연결,
Expansion Joint와 관련하여 이미지에서 확인되는 내용과
현재 이미지로 확인할 수 없는 내용을 설명해 주세요.
```

전체 문맥은 보이지만 Feeder 주변의 작은 글자는 작게 보입니다.

### 조건 B: Feeder #C 주변 확대 이미지와 같은 짧은 질문

전체 도면에서 Reception Bin 2와 Vibro Feeder #C 주변만 잘라 크게 만든 이미지를 제공합니다.

![Feeder #C 주변 확대 이미지](../assets/regions/feeder-c-area.png)

Feeder 이름과 태그는 크게 보이지만 제목란, 전체 범례와 일부 연결은 이미지 밖으로 사라집니다.

### 조건 C: 같은 확대 이미지와 근거 확인 질문

조건 B와 같은 이미지를 사용합니다. 대신 사람이 도면을 검토할 때 사용하는 확인 순서를 제공합니다.

```text
이 P&ID에서 Vibro Feeder #C를 찾아 다음 순서로 확인해 주세요.

1. 이미지에서 직접 읽은 장비명과 태그를 적습니다.
2. Feeder 바로 위쪽에 연결된 장비를 선을 따라 확인합니다.
3. Feeder 아래쪽 출구에서 이어지는 선과 설비를 확인합니다.
4. Expansion Joint로 해석할 수 있는 심벌이 있는지 범례와 비교합니다.
5. E-MT 또는 EM 표기가 보이면 motor 근거와 joint 근거를 구분합니다.
6. 직접 본 사실과 해석한 내용을 분리합니다.
7. 확인 범위를 벗어난 내용은 `확인하지 못함`으로 남깁니다.
```

이 프롬프트는 정답 대신 사람이 사용하는 확인 순서를 제공합니다.

## 실행한 모델과 평가 기준

본문에서는 다음 세 모델을 비교합니다.

- Claude Sonnet
- GPT-5.6 Luna
- GPT-5.6 Terra

Claude는 `claude -p`, Codex는 `codex exec --image`를 사용했습니다. 모든 실행은 새 세션에서 진행했습니다.

각 답변은 다음 네 항목으로 검토했습니다.

| 항목 | 확인할 내용 |
|---|---|
| Feeder 식별 | `VIBRO FEEDER #C`와 `11520-M-VB-03C`를 정확히 읽었습니까? |
| 위쪽 연결 | Reception Bin 2와의 연결을 확인했습니까? |
| 아래쪽 연결 | 이미지에서 보이는 선과 흐름 방향에 대한 해석을 구분했습니까? |
| Motor/joint 구분 | `E-MT`와 `EM`을 Expansion Joint 태그로 잘못 사용하지 않았습니까? |

각 항목은 1점이며 총 4점입니다. 이 점수는 모델의 일반적인 능력을 나타내는 점수가 아니라, 이번 도면과 질문에서 나타난 행동을 비교하기 위한 수동 검토 결과입니다.

## 이 실험의 기준 답안

모델 결과를 보기 전에 사람이 원본 도면에서 확인한 기준을 먼저 정리합니다.

| 확인 항목 | 기준 답안 |
|---|---|
| 장비명과 태그 | `VIBRO FEEDER #C`, `11520-M-VB-03C`가 보입니다. Unit 1과 Unit 2 표기가 함께 있습니다. |
| 바로 위쪽 연결 | `RECEPTION BIN 2`, 태그 `11520-M-SI-04`의 A측 하부 출구에서 내려오는 선이 `V186` 부근을 거쳐 Feeder #C로 연결됩니다. |
| 아래쪽 출구 연결 | Feeder #C 아래에서 수직 연결선이 계속 내려갑니다. 선의 최종 종점과 전체 흐름 방향은 전체 도면에서 이어서 확인할 항목으로 남깁니다. |
| Motor 표기 | 원 안의 `EM`과 `11520-E-MT-18`은 Feeder 구동 motor와 관련된 근거로 봅니다. |
| Expansion Joint | Feeder 연결부에 유연 연결부로 해석할 수 있는 심벌 후보가 보입니다. 확대 이미지에는 범례와 고유 joint 태그가 없으므로, 정확한 종류와 태그는 추가 확인 상태로 남깁니다. |

기준 답변을 문장으로 작성하면 다음과 같습니다.

> 이 P&ID에서 `VIBRO FEEDER #C`와 장비 태그 `11520-M-VB-03C`를 확인했습니다. Feeder 바로 위쪽은 `RECEPTION BIN 2(11520-M-SI-04)`의 A측 하부 출구와 연결됩니다. Feeder 아래쪽에서는 수직 연결선이 계속 내려갑니다. 선의 최종 종점과 흐름 방향은 전체 도면에서 이어서 확인할 항목으로 남깁니다. 원 안의 `EM`과 `11520-E-MT-18`은 motor 관련 표기로 봅니다. 연결부에는 Expansion Joint 후보 심벌이 보이며, 정확한 종류와 고유 태그는 범례와 전체 도면을 추가로 확인해야 합니다.

이 기준 답안은 `직접 읽은 글자`, `선을 따라 확인한 연결`, `설비 요소 해석`, `추가 확인 상태`를 구분합니다.

## 세 답변으로 핵심 차이를 확인합니다

아홉 개 답변을 모두 읽기 전에 성공, 오류, 확인 보류가 잘 드러나는 세 사례만 먼저 살펴보겠습니다.

### 전체 문맥을 사용해 안정적으로 답한 사례

> Vibro Feeder #C는 Reception Bin 2 아래에 있습니다. 장비 태그는 `11520-M-VB-03C`입니다. 아래쪽 출구는 Coal Feeder #C와 Pulverizer #C로 이어집니다. Expansion Joint의 정확한 개별 태그와 사양은 확인할 수 없습니다.

Codex Luna의 전체 도면 답변입니다. 장비와 위쪽 연결을 확인하고, joint의 고유 태그는 확인하지 못했다고 남겼습니다.

### 부분 확대 이미지에서 연결 방향을 과도하게 해석한 사례

> 장비 태그는 `11520-M-VB-03C`입니다. 위쪽은 `RECEPTION BIN 2`의 좌측 출구와 연결됩니다. Feeder 하부는 V188을 지나 `FROM COAL SILO C` 라인으로 연결됩니다.

Claude Sonnet은 작은 태그를 정확히 읽었지만 `FROM` 표기와 화살표를 충분히 고려하지 않고 연결 방향을 설명했습니다. 부분 확대 이미지가 글자를 키우는 동시에 전체 연결 문맥을 잘라낼 수 있음을 보여 줍니다.

### 근거 확인 순서가 확인 보류를 도운 사례

> `EM`과 `11520-E-MT-18`은 motor 관련 표기로 해석하는 것이 타당합니다. 빗살 형태의 기호는 Expansion Joint일 가능성이 있지만 범례가 없어 확인하지 못했습니다. Feeder 하부에 이어진 설비의 정확한 장비명과 태그는 확인하지 못했습니다.

Codex Terra는 일부 태그 오독을 남겼지만, 근거 확인 질문에서는 아래쪽 연결과 joint 의미를 단정하지 않고 보류했습니다.

모델과 조건별 아홉 개 답변을 모두 확인하려면 [첫 번째 실험의 모델별 상세 답변](01-experiment-answer-details.md)을 참고해 주세요.

## 이 실험에서 확인한 점

전체 도면은 연결 관계와 계통 문맥을 이해하는 데 도움이 되었습니다. 반면 작은 태그를 잘못 읽을 수 있었습니다.

부분 확대 이미지는 Feeder 이름과 태그를 크게 보여 주었습니다. 그러나 이미지 밖으로 나가는 연결과 `FROM` 표기의 방향을 잘못 해석하는 답이 발생했습니다.

근거 확인 프롬프트는 motor와 joint 구분을 개선했습니다. 하지만 태그 오독과 연결 방향 판단을 모든 모델에서 해결하지는 못했습니다.

따라서 이 실험은 다음 메시지를 전달합니다.

> 부분 확대와 단계별 프롬프트는 작은 글자와 설비 요소를 확인하는 데 사용하고, 전체 문맥과 연결선 검토를 함께 수행합니다.
