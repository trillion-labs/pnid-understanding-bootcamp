# 10. 초심자 관점 품질 검토 기록

## 검토 기준

모든 문장을 다음 질문으로 검토했다.

1. 이 용어를 앞에서 설명했는가?
2. 참가자가 지금 무엇을 해야 하는지 한 가지 행동으로 알 수 있는가?
3. 관찰, 해석, 미확인이 섞이지 않았는가?
4. 이미지와 좌표가 실제 파일과 일치하는가?
5. AI가 추측하지 못하게 범위와 완료 조건이 있는가?
6. 60분 안에 핵심 경험이 끝나는가?
7. 강사가 확장 범위를 선택할 여지가 있는가?

## 전체 흐름 검토

### 수정 전 문제

- P&ID 설명 전에 bbox, JSONL, IoU가 등장했다.
- 렌더링부터 정량 평가까지 모두 필수처럼 읽혔다.
- 90분, 반일, 2일 과정이 섞여 60분 기준이 보이지 않았다.
- 전체 도면 한 장을 AI에게 주는 실패와 개선 전략이 교육 중심에 없었다.
- `숙제` 범위를 자료가 미리 결정했다.

### 수정 결과

- P&ID 입문을 첫 문서로 배치했다.
- 위치 상자라는 쉬운 말 뒤에 bbox 용어를 소개합니다.
- 60분 시간표를 분 단위로 고정했다.
- 핵심 경로와 확장 경로를 분리하고, 실제 범위는 강사가 선택하도록 했다.
- baseline과 coarse-to-fine 비교를 수업 중심 실험으로 바꿨다.

## 문서별 검토

### README

- 첫 문장에서 60분 입문 실습임을 밝힘
- 학습 순서를 P&ID → prompting → agent → bbox → data → evaluation으로 교정
- 저해상도 overview, 사분면, 기능 crop 파일 위치 추가
- 원본 파일명과 실제 도면 ID를 분리

### 00 P&ID 입문

- 배관 및 계장도의 쉬운 정의 추가
- 실제 배치도와 다르다는 오해 방지
- 제목란, 장비, 선, 계기, 범례만 우선 소개
- 프로젝트별 태그 규칙 확인 필요성 명시
- 실제 운전·설계 판단과 교육의 안전 경계 명시

### 01 교육 설계

- 60분 합계 확인: 5+7+8+8+10+12+7+3=60분
- 객체 하나와 검토 한 번을 최소 성공 경험으로 정의
- 후속 활동을 숙제가 아닌 확장 경로 후보로 표현
- 도구 문제 발생 시 축소 가능한 구간 명시

### 02 시각 프롬프팅 전략

- 전체 저해상도 이미지는 지도용이라고 명시
- 작은 태그를 전체 이미지에서 읽히지 않도록 제한
- 4사분면에 10~15% 겹침을 두는 이유 설명
- 기계적 사분면과 기능별 crop의 차이 설명
- 장비, 문자, 연결선, 검토를 서로 다른 pass로 분리
- 확대 후 전체 이미지로 돌아가는 재검증 단계 추가
- Haiku baseline과 개선 run의 비교 항목 정의

### 03 위치 상자

- bbox를 투명 사각형 스티커 비유로 먼저 설명
- 좌표 계산은 두 번째 단계로 이동
- region bbox와 object bbox의 목적 차이 명시
- E01, E02, E03 overlay를 원본과 다시 비교
- E01 bbox를 `[475,650,845,975]`로 교정
- local/global 좌표 변환값을 함께 교정

### 04 데이터 모델

- JSON 전에 사람에게 익숙한 표 한 행 제시
- confidence와 review_status가 다른 질문임을 설명
- 본문 예시와 실제 JSONL 필드 일치 확인
- 자동 검사와 사람 검사의 역할 분리

### 05 에이전트 운영

- 전체 자동화 요청보다 객체 하나 요청을 먼저 배치
- 목표, 입력, 규칙, 출력, 검사 요소를 눈에 보이게 구성
- extractor와 reviewer의 역할 차이 설명
- 모델 합의를 정답으로 오해하지 않도록 경고

### 06 평가

- 수식 전에 확인됨, 수정 필요, 판독 불가를 제시
- `AI가 말했다`는 근거가 아님을 명시
- IoU와 precision/recall은 확장 평가로 이동
- 결과 평가와 작업 과정 평가를 분리
- 오류 taxonomy에 좌표, 추측, 불확실성 오류 포함

### 07 강사용 진행안

- 첫 질문부터 coarse-to-fine 실험에 집중
- baseline 결과를 그대로 보존하도록 지시
- 각 시간 구간에 참가자 행동과 강사 메시지 포함
- bbox 숫자를 측정하기 전에 위치 상자로 이해시킴
- 마지막에 전체 이미지 재검증을 필수로 유지
- 시간이 부족할 때 줄일 순서와 생략하지 않을 요소 제시

### 08 프롬프트 카드

- 탐색형 baseline을 유효한 용도로 설명하고 추출형 프롬프트와 목적 적합성을 비교
- 전체 지도, 사분면, 기능 crop, 전체 재검증 카드를 추가
- 좌표가 어려운 참가자를 위한 쉬운 위치 표현 대안 추가
- 추측 금지와 기존 후보만 검토하는 제한 포함

### 09 파일 준비 참고

- 렌더링 절차를 핵심 흐름에서 분리
- 300dpi 기준과 결과 이미지 크기 일치 확인
- PDF 텍스트 0줄의 의미 설명
- 명령어 암기가 목표가 아님을 명시

## 데이터 일관성 검토

- 원본 SHA-256 유지
- PDF 이름 `sample-pid.pdf` 반영
- JSON과 JSONL 문법 검사
- 모든 bbox가 이미지 경계 안에 있음
- R02 local 좌표 + region 원점 = global 좌표 확인
- 문서 예시와 `data/objects.example.jsonl` 좌표 동기화
- confidence와 review_status 의미 충돌 해소

## 강사가 최종 선택할 항목

자료는 다음 선택을 강제하지 않습니다.

- 참가자가 렌더링 명령을 직접 실행할지
- bbox 좌표를 직접 측정할지
- JSONL을 수업 중 작성할지
- Claude와 Codex를 모두 사용할지
- IoU·precision·recall까지 다룰지
- 확장 활동을 수업, 후속 과제 또는 별도 과정으로 둘지

## 남은 운영 리스크

- 실제 모델 UI에서 이미지가 자동 축소되는 방식은 실행 환경에 따라 다를 수 있습니다.
- 모델 응답은 실행마다 달라질 수 있으므로 baseline 정답을 고정하지 않습니다.
- 사분면은 연결선을 완전히 보존하지 못하므로 겹침과 전체 재검증이 필요합니다.
- P&ID 심벌과 태그 의미는 프로젝트 규칙 및 관련 도면 확인이 필요합니다.
- 실제 안전·운전 판단에는 이 교육 산출물을 사용하지 않습니다.

## 따라 하기 키트 추가 검토

- 참가자 시작 파일을 `README.md`와 `MY-WORK.md` 두 개로 제한
- 전체 overview, R02 확대본, bbox 표시본을 쉬운 번호 파일명으로 복사
- baseline 대화 A와 단계별 대화 B를 분리해 컨텍스트 오염 방지
- 모든 프롬프트를 복사 가능한 코드 블록으로 제공
- 각 단계에서 참가자가 기록할 위치를 `MY-WORK.md`와 일치시킴
- 모델 실패 시 사용할 대표 응답과 완성 기록 예시 준비
- 준비 검사 스크립트를 실제 실행해 READY 결과 확인
- 참가자 키트 이미지가 원본 asset과 같은 체크섬인지 확인

## 사용자 선호 재감사 반영

후속 피드백을 기준으로 자료 전체 흐름을 다시 감사했다.

- 핵심 실습을 쉬운 예제에서 실제 Feeder #C 도면 질문과 확대 이미지로 변경
- R02/E01은 bbox와 text layer 확장 예시로 분리
- benchmark, evidence, improvement loop의 쉬운 정의를 START-HERE에 추가
- 60분 마지막 10분에 채점→오류 분류→한 변수 개선→재평가를 포함
- Claude Code/Codex 비교를 문체가 아닌 동일 업무 계약 기준으로 변경
- README를 참가자 학습 순서와 강사·확장 자료로 분리
- 모든 새 개념에 문제→역할→상황→형식 순서를 적용
- 자료가 숙제 범위를 결정하지 않고 강사가 확장 범위를 선택하도록 유지
- 비식별 마스크와 OCR 재생성 상태를 명시

앞으로의 편집 기준은 `docs/00-course-design-principles.md`에 고정했다.

## Trillion Labs 사례 figure 검토

- 최근 `31b...zip` export를 원본 그대로 `source/private/`에 보존
- 개인 메타데이터가 포함된 원본은 참가자 배포 대상에서 제외
- 내부 표의 overall, pixel, axis 값을 별도 CSV로 전사
- figure A: 입력 전략별 overall score
- figure B: 총 입력 픽셀과 score 비교
- figure C: split+zoom과 single-highres의 문제 유형별 차이
- 향상 사례뿐 아니라 material·multihop 하락도 함께 표시
- 동일 Gemini judge와 bias 가능성, 표본 수 미기재를 figure에 명시
- “항상 split/zoom”이 아니라 질문별 A/B 평가가 필요하다는 메시지로 해석

## 워크북 전면 개정

참가자 피드백에 따라 핵심 본문을 시간표 중심 강의안에서 독립적으로 읽을 수 있는 워크북으로 다시 작성했습니다.

- 핵심 본문 전체를 `입니다/합니다`체로 통일했습니다.
- 각 단원을 결론→앞 단원 연결→실제 사례→개념 설명→직접 확인→다음 단원 연결 순서로 작성했습니다.
- Course Design 문서를 강사용 원칙이 아니라 워크북 안내와 Feeder #C 현업 상황 설명으로 교체했습니다.
- P&ID Primer에 도면 구성요소, 전문가의 Feeder #C 판단 흐름과 단계별 이미지를 추가했습니다.
- Program Design 문서를 Claude Code/Codex 실제 CLI 12회 비교 실험으로 교체했습니다.
- Visual Prompting 단원을 실제 오류에서 시작하도록 다시 작성했습니다.
- Trillion Labs 본문 figure를 네 개의 핵심 막대만 남긴 요약형으로 교체했습니다.
- Claude와 OpenAI 공식 이미지 token 규칙으로 이미지당 API 등가 비용을 계산했습니다.
- 위치 상자, 구조화 데이터, agent workflow, 평가, 개선 Loop 단원을 줄글 중심의 워크북 형태로 전면 개정했습니다.
- 12개 raw CLI 결과, 수동 evidence 검토, usage와 비용 근거를 프로젝트에 보존했습니다.
