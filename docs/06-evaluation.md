# P&ID 에이전트의 답을 평가하는 방법

> 평가하기 좋은 질문은 정답이 명확하고, 각 값을 원본에서 다시 확인할 수 있으며, 맞고 틀림을 같은 규칙으로 판단할 수 있어야 합니다.

이 워크북에서는 P&ID 한 장만 사용합니다. 모델이 관련 도면을 찾았는지가 아니라, 지정된 장비와 연결을 얼마나 정확히 읽었는지 평가합니다.

## 평가할 질문과 정답을 먼저 고정합니다

질문은 다음과 같습니다.

> 이 P&ID에서 Reception Bin 2의 A측 하부 출구와 연결된 Vibro Feeder #C를 찾아 주세요. Reception Bin 2의 장비 태그, A측 밸브 번호, Feeder #C의 장비 태그, 연결된 전동기의 심벌 표기와 태그를 그대로 적어 주세요.

사람이 원본을 검토하여 만든 기준 답안은 다음과 같습니다.

| 평가 항목 | 기준 답안 | 원본에서 확인하는 위치 |
|---|---|---|
| Reception Bin 2 장비 태그 | `11520-M-SI-04` | `RECEPTION BIN 2` 바로 아래 |
| A측 하부 출구 밸브 | `V186` | Bin 하부 `A` 표시에서 내려가는 선 |
| Vibro Feeder #C 장비 태그 | Unit 1과 Unit 2 모두 `11520-M-VB-03C` | V186 아래의 Feeder #C 표기 옆 |
| Feeder #C 전동기 | 원 안의 `EM`, 태그 `11520-E-MT-18` | Feeder #C 바로 오른쪽 |

오른쪽의 `11520-E-MT-19`는 다른 Feeder에 연결된 전동기입니다. Feeder #C의 답으로 적으면 전동기 항목은 오답입니다.

## 네 항목을 각각 1점으로 채점합니다

각 항목의 문자열을 모두 정확히 읽으면 1점입니다.

- 일부 문자만 맞으면 0점입니다.
- 정답과 잘못된 값을 함께 적어도 0점입니다.
- 읽지 못했다고 정직하게 보류하면 틀린 값을 만든 것은 아니지만 정답을 확인하지 못했으므로 0점입니다.
- 연결 관계 설명이 자연스러워도 문자열이 틀리면 해당 항목은 0점입니다.

총점은 4점입니다. 모델의 일반적인 능력이 아니라 이번 이미지와 질문에서 나타난 판독 결과를 비교하는 점수입니다.

## 실제 실행을 채점한 결과

| 모델 | 전체 도면+짧은 질문 | 부분 확대+짧은 질문 | 부분 확대+단계별 질문 |
|---|---:|---:|---:|
| Claude Sonnet | 3/4 | 4/4 | 4/4 |
| Codex Luna | 2/4 | 4/4 | 4/4 |
| Codex Terra | 2/4 | 4/4 | 3/4 |

부분 확대 이미지와 짧은 질문에서는 세 모델이 모두 4점을 받았습니다. 질문의 네 정답이 한 화면에 충분히 크게 보였기 때문입니다.

단계별 질문은 Sonnet과 Luna의 점수를 유지했지만 Terra에는 새로운 오류를 만들었습니다. Unit 1 태그를 오른쪽 Feeder의 `03B`와 섞어 읽었습니다.

## 점수와 함께 상태를 남깁니다

같은 0점이라도 잘못된 값을 만든 경우와 읽지 못했다고 보류한 경우는 다릅니다.

| 상태 | 의미 | 예시 |
|---|---|---|
| 확인됨 | 기준 답안과 문자열이 일치하고 원본 위치를 확인했습니다. | `V186`을 A측 선에서 확인했습니다. |
| 수정 필요 | 값을 적었지만 문자열이나 소속이 틀렸습니다. | `M-VB-03C`를 `M-V-03C`로 읽었습니다. |
| 확인하지 못함 | 현재 이미지로 읽지 못해 값을 비워 두었습니다. | 전체 이미지에서 전동기 태그를 보류했습니다. |

`확인하지 못함`은 정확도 점수를 얻지는 못하지만 근거 없는 값을 만드는 것보다 안전한 행동입니다. 따라서 점수와 행동 상태를 함께 기록합니다.

## 오류를 원인별로 나눕니다

| 오류 유형 | 실제 예시 | 다음에 검토할 것 |
|---|---|---|
| 작은 글자 판독 오류 | Luna가 `M-VB-03C`를 `M-V-03C`로 읽었습니다. | 부분 확대 이미지의 해상도와 범위를 확인합니다. |
| 다른 종류의 표기 혼동 | Sonnet이 전동기를 `M-TP16`으로 답했습니다. | 대상 장비에 직접 연결된 심벌을 따라갑니다. |
| 인접 태그 혼동 | Terra가 Unit 1 값을 오른쪽의 `03B`와 섞었습니다. | 태그와 장비 사이의 위치 관계를 확인합니다. |
| 판독 보류 | Terra가 전체 이미지에서 Feeder와 전동기 태그를 읽지 못했습니다. | 더 선명한 부분 확대 이미지를 제공합니다. |

오류 유형을 기록하면 무엇을 바꿔야 하는지 구체적으로 정할 수 있습니다. 판독 오류에는 이미지가, 소속 관계 오류에는 근거 위치와 확인 규칙이 더 직접적인 개선 대상입니다.

## 위치 근거도 함께 확인합니다

문자열이 맞아도 모델이 어디에서 읽었는지 알 수 없다면 다른 사람이 답을 다시 검토하기 어렵습니다.

다음 세 가지를 확인합니다.

1. Reception Bin 2부터 전동기까지 필요한 구역이 근거 이미지에 포함되어 있습니까?
2. 네 문자열이 각각 어느 장비와 선에 속하는지 설명했습니까?
3. 오른쪽 Feeder와 전동기를 제외한 이유를 원본 위치로 확인할 수 있습니까?

이 질문의 파란 근거 구역은 네 값을 한 번에 검토하기 위한 넓은 위치 상자입니다. 상자를 무조건 작게 만드는 것이 아니라 판단에 필요한 문맥을 포함하는 것이 중요합니다.

## 품질을 통과한 뒤 비용을 비교합니다

먼저 4점과 근거 요구사항을 통과한 결과끼리 비교합니다. 그다음 다음 항목을 봅니다.

- 실행 시간
- 도구 호출 수
- 입력, 캐시 입력과 출력 token
- CLI가 보고한 비용
- 공식 API 단가로 환산한 비교용 추정 비용

예를 들어 Sonnet은 부분 확대+짧은 질문에서 4점을 받았고 CLI 보고 비용은 약 $0.050이었습니다. 같은 확대 이미지에 단계별 질문을 추가한 조건도 4점이었지만 약 $0.056이었습니다. 이번 한 번의 실행에서는 더 긴 질문이 추가 점수를 만들지 않았습니다.

비용 차이가 작더라도 평가 기준을 통과하지 못한 결과와 직접 비교하지 않습니다. 빠르게 틀린 답을 만드는 것은 개선이 아니기 때문입니다.
