# P&ID 에이전트의 답을 평가하는 방법

> P&ID 에이전트의 답은 문장이 자연스러운지만 보고 평가할 수 없습니다. 질문의 핵심 단서를 실제 이미지에서 확인하고, 관찰과 해석을 구분하며, 확인하지 못한 내용을 추측하지 않아야 합니다.

앞 단원에서는 Claude Code와 Codex에 같은 업무 계약을 전달했습니다. 이제 어떤 결과를 더 좋은 결과라고 판단할지 기준을 정하겠습니다.

## 먼저 무엇을 평가하는지 고정합니다

여러 P&ID 가운데 관련 시트를 고르는 `도면 검색 작업`과, 선택된 한 장에서 장비와 연결을 읽는 `단일 도면 이해 작업`은 서로 다른 기준으로 평가해야 합니다.

이 워크북의 중심은 단일 도면 이해 작업입니다. 입력으로 `J-11520-ZM-105-005` 한 장을 제공하고, Feeder #C의 장비 태그와 주변 연결을 얼마나 정확하고 신중하게 읽는지 평가합니다.

```text
입력: 선택된 P&ID 한 장 또는 그 일부
질문: Feeder #C의 태그, 위쪽 장비, 아래쪽 연결과 joint 근거
출력: 확인한 내용, 원본 위치, 해석과 확인하지 못한 내용
```

평가 대상이 이렇게 고정되어야 이미지 입력이나 프롬프트를 바꾼 전후 결과를 공정하게 비교할 수 있습니다.

## 기준 답안을 먼저 만듭니다

에이전트 결과를 보기 전에 사람이 원본 도면을 검토하여 기준 답안을 만듭니다. 평가 분야에서는 이를 `gold answer` 또는 `gold data`라고도 부릅니다.

이 질문의 기준 답안은 다음과 같습니다.

| 확인 항목 | 기준 답안 |
|---|---|
| 장비명과 태그 | `VIBRO FEEDER #C`, `11520-M-VB-03C`가 보입니다. |
| 바로 위쪽 연결 | `RECEPTION BIN 2(11520-M-SI-04)`의 A측 하부 출구와 연결됩니다. |
| 아래쪽 연결 | Feeder 아래에서 수직선이 계속 내려갑니다. 부분 확대 이미지만으로 최종 종점과 흐름 방향을 확정하지 않습니다. |
| Motor 표기 | 원 안의 `EM`과 `11520-E-MT-18`은 motor 관련 근거로 봅니다. |
| Expansion Joint | 유연 연결부로 해석할 수 있는 심벌 후보가 보입니다. 정확한 종류와 고유 태그는 현재 확대 이미지로 확정하지 않습니다. |

기준 답안에는 정답 문자열만 넣지 않습니다. 직접 읽은 글자, 선을 따라 확인한 연결, 설비 요소 해석, 확인을 보류할 내용을 구분해야 합니다.

## 네 가지 질문으로 답을 채점합니다

첫 번째 실험에서는 다음 네 항목을 각각 1점으로 평가했습니다.

| 항목 | 1점을 주는 기준 |
|---|---|
| Feeder 식별 | `VIBRO FEEDER #C`와 `11520-M-VB-03C`를 정확히 읽었습니다. |
| 위쪽 연결 | Reception Bin 2와의 연결을 선을 따라 확인했습니다. |
| 아래쪽 연결 | 이미지에서 보이는 선과 흐름 방향에 대한 해석을 구분했습니다. |
| Motor와 joint 구분 | `E-MT`와 `EM`을 Expansion Joint 태그로 사용하지 않았습니다. |

총점은 4점입니다. 이 점수는 모델의 일반적인 능력을 나타내지 않습니다. 이번 도면, 이미지 입력과 질문에서 나타난 행동을 비교하기 위한 점수입니다.

실제 결과는 다음과 같았습니다.

| 모델 | 전체 도면+짧은 질문 | 부분 확대+짧은 질문 | 부분 확대+근거 확인 질문 |
|---|---:|---:|---:|
| Claude Sonnet | 3/4 | 3/4 | 3/4 |
| Codex Luna | 4/4 | 3/4 | 3/4 |
| Codex Terra | 3/4 | 2/4 | 3/4 |

부분 확대 이미지는 작은 글자를 읽는 데 도움이 되었지만 연결 방향 해석 오류를 만들었습니다. 근거 확인 순서는 motor와 joint 구분을 도왔지만 태그 오독과 아래쪽 연결 해석을 모든 모델에서 해결하지는 못했습니다.

## 점수와 함께 검토 상태를 남깁니다

점수만 남기면 어떤 내용을 고쳐야 하는지 알기 어렵습니다. 각 근거 행을 다음 세 상태로 나눕니다.

| 상태 | 의미 | 다음 행동 |
|---|---|---|
| 확인됨 | 글자, 심벌과 위치를 원본에서 확인했습니다. | 결과를 유지합니다. |
| 수정 필요 | 대상은 있지만 글자·위치·설비 요소 해석이 틀렸습니다. | 원래 값과 수정값을 함께 기록합니다. |
| 확인하지 못함 | 현재 이미지와 자료로 확정할 수 없습니다. | 값을 채우지 않고 추가 자료를 요청합니다. |

`AI가 그렇게 말했습니다`는 원본 근거가 아닙니다. 검토자는 같은 이미지 위치에서 글자와 심벌을 다시 확인합니다.

## 오류를 원인별로 기록합니다

같은 3점이라도 발생한 오류는 다를 수 있습니다.

| 오류 유형 | 예시 | 다음에 검토할 것 |
|---|---|---|
| 판독 오류 | `M-VB-03C`를 `M-FE-03C`로 읽었습니다. | 더 선명한 부분 확대 이미지와 문자 소속 관계를 확인합니다. |
| 연결 오류 | `FROM COAL SILO C`를 Feeder 출구 방향으로 설명했습니다. | 화살표 방향과 전체 도면의 연결을 다시 확인합니다. |
| 설비 요소 해석 오류 | `E-MT-18`을 Expansion Joint 태그로 사용했습니다. | 관찰한 문자열과 해석한 설비 요소를 분리합니다. |
| 근거 부족 | 답은 맞지만 원본 위치가 없습니다. | 위치 상자나 근거 이미지를 추가합니다. |
| 과도한 확정 | 범례가 없는데 joint 종류를 확정했습니다. | 확인하지 못함 상태를 허용합니다. |

오류 유형이 있으면 다음 개선 대상을 구체적으로 고를 수 있습니다. 판독 오류라면 이미지 입력을, 해석 오류라면 지침과 데이터 구조를 먼저 살펴볼 수 있습니다.

## 위치 상자는 필요할 때만 별도로 평가합니다

위치 상자를 평가할 때에는 상자의 목적을 먼저 구분합니다.

- 객체 하나를 찾는 작업은 정답 상자와 예측 상자가 얼마나 겹치는지 평가할 수 있습니다.
- 여러 단서를 함께 보여 주는 근거 구역은 필요한 단서가 모두 포함되었는지 평가해야 합니다.

Feeder #C의 파란 근거 구역은 장비명, 태그, motor 표기와 출구 연결을 함께 보여 주기 위한 넓은 상자입니다. 이런 상자를 단순히 작게 만드는 것은 개선이 아닙니다. 다른 검토자가 같은 판단을 재현할 수 있는 문맥이 포함되어야 합니다.

## 품질을 통과한 뒤 비용을 비교합니다

효율은 품질 점수에 바로 더하지 않습니다. 먼저 기준 답안과 근거 요구사항을 통과한 결과끼리 비교합니다.

기록할 항목은 다음과 같습니다.

- 실행 시간
- 도구 호출과 대화 횟수
- 입력, 캐시 입력과 출력 token
- CLI가 보고한 비용
- 공식 API 단가로 환산한 비교용 추정 비용

빠르게 틀린 답을 만드는 것은 개선이 아닙니다. 같은 품질이라면 더 적은 이미지와 token을 사용한 방법을 선택할 수 있습니다.

## 도면 검색 평가는 별도로 확장합니다

여러 P&ID에서 관련 시트를 찾는 작업을 평가하려면 다음 항목을 추가합니다.

| 영역 | 확인할 내용 |
|---|---|
| 도면 선택 | 기대한 도면번호와 revision을 선택했습니까? |
| 후보 수 | 하나를 요구했을 때 불필요한 후보를 여러 개 제시하지 않았습니까? |
| 선택 근거 | 파일명만이 아니라 질문의 장비와 연결 근거를 이미지에서 확인했습니까? |
| 확인 보류 | 제공된 자료로 선택할 수 없을 때 그 이유를 설명했습니까? |

도면 검색 점수와 단일 도면 이해 점수를 섞지 않습니다. 도면을 맞게 골랐어도 내부 장비를 잘못 설명할 수 있고, 한 장을 잘 읽어도 여러 파일 가운데 그 시트를 찾지 못할 수 있기 때문입니다.
