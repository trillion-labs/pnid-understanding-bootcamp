# 이 워크북에서 무엇을 배우게 되나요?

이 워크북은 P&ID를 처음 보는 분이 Claude Code나 Codex 같은 AI 에이전트와 함께 실제 도면을 다루는 과정을 처음부터 끝까지 경험할 수 있도록 만든 안내서입니다.

이 워크북을 통해 다음을 배울 수 있습니다.

1. AI 에이전트에게 도면을 주고 질문하는 방법
2. AI 에이전트에게 도면을 좀 더 효율적으로 보여 주는 방법
3. 도면을 AI가 더 쉽게 다룰 수 있도록 구조화하는 방법
4. AI의 답변을 검증하고 개선하는 방법

예시 P&ID 한 장과 질문을 가지고 직접 실행하고, 답변을 관찰하고, 개선한 뒤 다시 실행해 보는 과정을 수행할 것입니다. 이를 통해 AI 에이전트의 이해도를 높이고, 실제 업무에 적용할 수 있는 방법을 익힐 수 있습니다.

## 우리가 사용할 질문

이 워크북에서는 처음부터 끝까지 같은 P&ID 한 장을 사용합니다.

워크북 전체에서 중심이 되는 질문은 다음과 같습니다.

> 이 P&ID에서 `RECEPTION BIN 2`의 A측 하부 출구와 연결된 `VIBRO FEEDER #C`를 찾아 주세요. 도면에 직접 표시된 ① Reception Bin 2의 장비 태그, ② A측 하부 출구의 밸브 번호, ③ Vibro Feeder #C의 장비 태그, ④ Feeder #C에 연결된 전동기의 심벌 표기와 태그를 그대로 적고 연결 관계를 설명해 주세요.

이 질문은 도면 안에서 장비를 찾고 연결선을 따라가며 정확한 글자를 읽는 작업입니다. 처음 보면 영어 장비 이름과 태그가 섞여 있어 어렵게 느껴질 수 있으므로 하나씩 풀어보겠습니다.

- `Reception Bin 2`는 고체 물질을 잠시 받아 두는 두 번째 저장 용기입니다.
- `A측 하부 출구`는 Bin 아래쪽의 두 출구 가운데 `A`라고 적힌 쪽입니다.
- `V186`처럼 `V`로 시작하는 표기는 이 도면에서 밸브를 구분하는 번호입니다.
- `Vibro Feeder`는 진동을 이용하여 고체 물질을 다음 설비로 보내는 장비입니다.
- `#C`는 여러 Vibro Feeder 가운데 C번 장비를 가리킵니다.
- 원 안의 `EM`은 Feeder를 구동하는 전동기 심벌입니다.

따라서 이 질문을 쉬운 말로 바꾸면 다음과 같습니다.

> Reception Bin 2 아래에서 A라고 적힌 출구를 찾고 선을 아래로 따라가세요. 그 선에 있는 밸브와 C번 진동 피더, 피더를 움직이는 전동기에 적힌 번호를 그대로 읽어 주세요.

이 질문의 답은 원본 도면에서 다음과 같이 확인할 수 있습니다.

| 확인 항목 | 기준 답안 |
|---|---|
| Reception Bin 2의 장비 태그 | `11520-M-SI-04` |
| A측 하부 출구의 밸브 번호 | `V186` |
| Vibro Feeder #C의 장비 태그 | `11520-M-VB-03C` |
| Feeder #C 전동기 | 원 안의 `EM`, 태그 `11520-E-MT-18` |

연결 순서는 `RECEPTION BIN 2 → A측 하부 출구 → V186 → VIBRO FEEDER #C → EM / 11520-E-MT-18`입니다. 각 값이 맞는지 문자열 단위로 채점할 수 있으므로 모델 답변을 비교하기도 쉽습니다.

## 왜 이 질문이 AI 에이전트 실습에 적합한가요?

이 질문에는 단순히 글자 하나를 복사하는 것보다 조금 더 깊은 도면 읽기가 필요합니다.

먼저 전체 도면에서 Reception Bin이 반복되는 구조를 파악하고 그중 2번 Bin을 찾아야 합니다. 그다음 Bin 하부의 `A` 표시에서 선을 아래로 따라 `V186`과 Feeder #C를 연결해야 합니다.

마지막으로 Feeder #C 옆의 `EM / 11520-E-MT-18`과 오른쪽 Feeder 옆의 `EM / 11520-E-MT-19`를 구분해야 합니다. 실제 에이전트 실행에서는 전체 이미지만 제공했을 때 일부 모델이 Feeder 태그와 전동기 태그를 잘못 읽었습니다.

이 질문 하나만으로도 다음 능력을 모두 확인할 수 있습니다.

1. 큰 도면에서 필요한 구역을 선택하는 능력
2. 연결선을 따라 장비 관계를 확인하는 능력
3. 작은 장비명과 태그를 정확히 읽는 능력
4. 서로 가까운 Feeder와 전동기 태그를 구분하는 능력
5. 읽지 못한 값을 추측하지 않는 능력
6. 답의 근거를 사람이 다시 확인할 수 있도록 남기는 능력

## 워크북은 어떤 순서로 진행되나요?

각 단원은 앞 단원의 결과를 다음 단원의 입력으로 사용합니다. 중간에 기술 용어가 갑자기 등장하지 않도록, 먼저 문제가 무엇인지 살펴본 뒤 필요한 개념을 소개합니다.

### 1단원: P&ID라는 도면을 이해합니다

먼저 P&ID가 무엇인지, 일반 배치도와 무엇이 다른지 알아봅니다. 제목란, 장비, 배관선, 계기, 태그와 범례를 실제 그림에서 하나씩 찾아봅니다.

이 단원의 마지막에는 P&ID 전문가가 현업 질문을 받았을 때 어떤 순서로 생각하는지 따라가 봅니다. 이후 단원에서 AI가 놓친 부분을 사람이 어떻게 개선할 수 있을지에 대한 기초를 다집니다.

### 2단원: 같은 도면을 서로 다른 방식으로 AI에게 보여 줍니다

전체 도면 한 장을 그대로 보여 준 결과와, 필요한 구역만 확대해서 보여 준 결과를 비교합니다. 본문에서는 Claude Sonnet, Codex Luna, Codex Terra를 실제 CLI로 실행한 결과를 사용합니다.

### 3단원: AI 답에 원본 위치를 연결합니다

AI가 `VIBRO FEEDER #C가 보입니다`라고 답해도, 그 글자가 도면 어디에 있었는지 남기지 않으면 다른 사람이 다시 확인하기 어렵습니다.

이때 사용하는 것이 위치 상자입니다. 컴퓨터 비전에서는 bounding box, 줄여서 bbox라고 부릅니다. bbox를 사용해서 특정 설비의 위치를 명확하게 지정하는 방법을 배웁니다.

### 4단원: P&ID와 AI 답변을 다시 사용할 수 있는 데이터로 바꿉니다

먼저 도면의 기본정보와 한 줄 요약을 기록하고, Reception Bin 1·2·3처럼 다시 찾아볼 큰 구역과 주요 태그를 JSON에 단계적으로 추가합니다. 모든 객체와 연결을 추출하지 않고 도면의 의미와 탐색 위치를 빠르게 파악할 수 있는 수준으로 정리합니다.

그다음 AI의 설명을 표 형식으로 정리합니다. 도면 자체를 위한 색인과 특정 질문에 대한 AI 답변을 구분하여, 여러 실행의 결과를 쉽게 검색하고 비교할 수 있도록 합니다.

### 5단원: 단일 도면 이해 질문으로 성능을 측정합니다

준비된 한 줄 명령으로 Claude Code와 Codex를 직접 실행하고 결과를 텍스트 파일로 저장합니다. 그다음 Reception Bin 태그, A측 밸브, Feeder 태그, 전동기 태그를 각각 채점합니다. 시간과 토큰 비용은 품질 점수와 별도로 기록합니다.

### 6단원: 한 가지를 개선하고 같은 조건으로 다시 평가합니다

모델, 이미지, 프롬프트를 모두 한 번에 바꾸면 무엇 때문에 결과가 달라졌는지 알 수 없습니다. 따라서 오류를 먼저 분류하고 데이터, 도구, 프롬프트, 스킬 가운데 하나만 변경합니다.

그다음 새 세션에서 같은 질문을 다시 실행합니다. 이것이 이 워크북에서 말하는 개선 과정입니다.

## 이 워크북에서 사용하는 파일

원본 P&ID는 비공개 `source/sample-pid.pdf`에 보존되어 있습니다. 워크북에서 사용하는 공개 이미지에는 회사명, 로고, 주소와 작성자 정보가 보이지 않도록 마스크가 적용되어 있습니다.

워크북에서 사용하는 이미지는 이미 준비되어 있습니다.

- `assets/overview/sample-pid-overview-1600.png`: 도면 전체 구조를 보는 이미지입니다.
- `assets/regions/feeder-c-area.png`: C번 Vibro Feeder 주변을 크게 보여 주는 이미지입니다.
- `assets/bbox/feeder-c-query-evidence.png`: 질문과 관련된 근거 위치를 표시한 이미지입니다.
- `assets/ocr/sample-pid-ocr.pdf`: OCR 텍스트 검색을 실험하는 교육용 PDF입니다.

독자는 PDF 변환이나 이미지 분할부터 시작하지 않아도 됩니다. 준비된 파일로 먼저 개념과 작업 흐름을 이해한 뒤, 필요하면 부록의 이미지 준비 과정으로 확장할 수 있습니다.

## 이 워크북에서 결과를 읽는 기준

AI가 답을 길게 작성했다고 해서 더 좋은 결과는 아닙니다. 다음 질문에 답할 수 있어야 합니다.

- 어떤 원본 파일을 확인했습니까?
- 도면에서 직접 읽은 글자는 무엇입니까?
- 장비나 심벌의 의미를 어떻게 해석했습니까?
- 그 근거는 이미지 어디에 있습니까?
- 확인하지 못한 내용은 무엇입니까?
- 다른 사람이 같은 위치를 보고 판단을 재현할 수 있습니까?

이 기준은 Claude Code와 Codex 모두에 동일하게 적용됩니다. 두 제품의 문체나 답변 길이를 비교하는 것이 아니라, 같은 업무 질문에 대해 확인 가능한 결과를 얼마나 잘 만들었는지 비교합니다.

## 다음 단원으로 넘어가기 전에

이제 우리가 풀어야 할 현업 질문이 무엇인지 알았습니다. 다음 단원에서는 AI를 사용하기 전에 먼저 P&ID 자체를 읽어봅니다.

P&ID를 완벽하게 해독하는 것이 목표는 아닙니다. 도면에서 무엇이 직접 보이고, 무엇은 범례나 공정 지식을 이용한 해석이며, 무엇은 아직 확인할 수 없는지를 구분할 수 있으면 충분합니다. 이 구분이 이후 모든 AI 검토의 기준이 됩니다.
