# 프롬프트 카드

복사해서 사용하되 파일 경로와 분석 구역 이름은 작업에 맞게 바꿉니다.

## 프롬프트는 목적에 따라 평가합니다

짧거나 넓은 프롬프트가 곧 나쁜 프롬프트는 아닙니다.

| 프롬프트 종류 | 잘 맞는 목적 | 부족할 수 있는 목적 |
|---|---|---|
| 탐색형 | 처음 훑기, 예상하지 못한 특징 발견, 대화 시작 | 재현 가능한 추출, 정량 평가 |
| 지도형 | 큰 구조와 확대 우선순위 찾기 | 작은 태그 판독 |
| 추출형 | 정해진 대상과 필드를 표로 저장 | 자유로운 해석과 아이디어 탐색 |
| 검토형 | 기존 결과의 근거 확인 | 새로운 후보 발굴 |

좋은 프롬프트의 기준은 길이가 아니라 `현재 목적에 적합한가`입니다.

## 카드 0: 탐색형 baseline

> 이 도면을 분석해 주세요.

이 요청은 처음 도면을 자유롭게 훑거나 AI가 무엇을 먼저 보는지 관찰할 때 유용합니다. 다만 출력 범위, 근거 위치, 완료 조건이 없으므로 그대로 구조화 추출이나 평가에 사용하기에는 부족할 수 있습니다. 탐색 결과를 보존한 뒤 목적별 프롬프트와 비교할 수 있습니다.

## 카드 0-1: 전체 도면을 지도처럼 보기

> 이 이미지는 전체 구조를 파악하기 위한 저해상도 지도입니다. 작은 태그를 추측해 읽지 마세요. 제목란, 범례, 주요 장비 묶음, 반복 구조, 확대가 필요한 구역만 위치와 함께 설명해 주세요.

## 카드 0-2: 겹침 있는 사분면 보기

> 이 이미지는 전체 도면의 왼쪽 아래 확대 이미지이며 인접 구역과 일부 겹칩니다. 이 구역에서 완전히 보이는 장비와 경계에 잘린 장비를 구분해 주세요. 잘린 장비나 구역 밖으로 나가는 선은 확정하지 말고 `boundary_followup`으로 기록해 주세요.

## 카드 0-3: 기능별 부분 확대 이미지에서 한 종류만 보기

> 이 이미지는 전체 도면에서 Reception Bin 1 주변만 크게 만든 부분 확대 이미지입니다. 지금은 장비 본체와 장비 이름만 찾아 주세요. 계기 버블, 밸브, 연결 관계는 아직 추출하지 마세요. 각 후보에 보이는 글자, 종류 후보, 확신도, 판독 불가 문자를 분리해 기록해 주세요.

## 카드 0-4: 전체 도면으로 돌아가 확인하기

> Reception Bin 1 주변 확대 이미지에서 만든 기존 후보만 전체 이미지와 다시 대조해 주세요. 새로운 태그나 객체를 추가하지 마세요. 각 후보가 전체 도면의 어느 위치에 속하는지와 부분 확대 이미지 밖의 연결을 확인할 수 있는지 여부만 기록해 주세요.

## 카드 1: 읽기 전용 조사

> 아직 파일을 만들거나 수정하지 마세요. 작업 폴더와 입력 PDF를 조사해서 파일 존재 여부, 페이지 수, 페이지 크기, 회전, 암호화, 텍스트 추출 가능 여부를 보고해 주세요. 원본은 수정하지 않습니다. 다음 작업 계획과 확인이 필요한 위험만 제시하고 멈춰 주세요.

## 카드 2: 렌더링

> 원본 PDF의 1페이지를 300dpi PNG로 렌더링해 주세요. 출력 파일명은 문서 ID와 페이지 번호를 포함해 주세요. 완료 후 픽셀 너비와 높이를 확인하고 네 모서리, 얇은 선, 제목란이 잘리지 않았는지 시각적으로 검사해 주세요. 생성 파일, 이미지 크기와 검사 결과를 보고해 주세요.

## 카드 3: region 제안

> 전체 이미지를 기능적으로 읽을 수 있는 5~8개 분석 구역으로 제안해 주세요. 좌표는 원본 이미지 왼쪽 위를 원점으로 하는 픽셀 `[x_min,y_min,x_max,y_max]`를 사용해 주세요. 각 구역이 포함해야 할 문맥과 겹침이 필요한 이유를 설명하고, 아직 세부 객체 이름은 확정하지 마세요.

처음 학습할 때 좌표가 부담되면 마지막 문장을 다음처럼 바꿉니다.

> 아직 숫자 좌표를 만들지 말고 `왼쪽 위 / 중앙 / 오른쪽 아래`처럼 쉬운 위치 표현만 사용해.

## 카드 4: object 후보 추출

> Feeder #C 주변 확대 이미지에서 Reception Bin 2의 장비 태그, A측 밸브 번호, Feeder #C의 장비 태그, 연결된 전동기의 심벌과 태그를 확인해 주세요. 각 질문 단서에 observed_text_or_symbol, inferred_component, evidence_region, status, note를 작성해 주세요. 흐린 글자는 unknown으로 두고, 오른쪽 Feeder의 `03B`나 `E-MT-19`를 Feeder #C의 값으로 사용하지 마세요.

## 카드 5: reviewer

> 당신은 추출 작업과 독립된 검토자입니다. 기존 주석을 그대로 믿지 말고 원본 이미지에서 각 행을 다시 확인해 주세요. `confirmed`, `needs_correction`, `unreadable`, `unsupported` 중 하나로 판정하고 이유와 근거 위치를 적어 주세요. 직접 수정한 값과 원래 값을 모두 보존해 주세요.

## 카드 6: 자동 검사

> JSONL 모든 줄의 JSON 문법, 필수 필드, ID 중복, 위치 상자 좌표 순서, 이미지 경계, 관계 참조 ID와 근거 파일 존재 여부를 검사해 주세요. 오류를 파일명과 줄 번호로 보고해 주세요. 자동으로 의미를 추측해 고치지 말고 안전한 기계적 수정만 별도로 제안해 주세요.

## 카드 7: 평가

> 에이전트 결과와 기준 답안을 비교해 유형별 TP, FP, FN, precision, recall, F1을 계산해 주세요. 위치 상자 매칭 기준과 동률 처리 방법을 먼저 명시해 주세요. 글자와 관계 오류는 별도 표로 분리하고, 가장 빈번한 오류 유형 3개와 다음 실험 제안을 작성해 주세요.

## 카드 8: 완료 보고

> 작업을 종료하기 전에 생성·수정한 파일, 실행한 검사, 통과·실패 결과, 판독 불가 항목, 사람이 결정해야 할 항목과 재현 명령을 요약해 주세요. 검증하지 않은 항목을 완료로 표현하지 마세요.

## 넓은 요청을 목적에 맞게 구체화하는 실습

탐색 또는 위임용 요청:

> 이 도면 다 분석해서 엑셀로 만들어줘.

에이전트가 먼저 계획을 세우고 사용자와 범위를 조정한다면 이 요청으로도 작업을 시작할 수 있습니다. 결과 형식과 평가 기준을 재현 가능하게 만들고 싶다면 다음 질문을 추가로 정합니다.

구체화 질문:

- 어떤 페이지와 revision인가?
- 어떤 대상 class가 필요한가?
- bbox 좌표 기준은 무엇인가?
- 출력 스키마는 무엇인가?
- 읽을 수 없는 글자는 어떻게 처리하는가?
- 어떤 검사를 통과해야 하는가?
- 관계를 어디까지 추출하는가?
