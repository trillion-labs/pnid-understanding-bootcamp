# 이미지 확대와 프롬프트 비교 실험

앞 단원에서는 Reception Bin 2 주변의 장비와 태그를 읽었습니다. 이번에는 같은 네 항목을 Claude Sonnet, Codex Luna, Codex Terra에 맡기고, **이미지 범위**와 **프롬프트 상세도**가 판독 결과에 어떤 차이를 만드는지 비교합니다.

이 실험의 목적은 모델 순위를 정하는 것이 아닙니다. 전체 도면에서 작은 글자를 읽지 못했을 때 지시를 길게 쓰는 것과 필요한 구역을 크게 제공하는 것 가운데 무엇이 더 직접적인 개선인지 확인합니다.

## 먼저 비교 조건을 고정합니다

이번 실험은 다음 2×2 조건으로 구성합니다.

| 조건 | 이미지 | 프롬프트 |
|---|---|---|
| 실험 1 | 전체 도면 1600×1131 | 짧은 질문 |
| 실험 2 | 전체 도면 1600×1131 | 단계별 질문 |
| 실험 3 | 부분 확대 1244×1600 | 짧은 질문 |
| 실험 4 | 부분 확대 1244×1600 | 단계별 질문 |

각 실행은 이전 답변의 영향을 받지 않도록 **새 대화**에서 시작합니다. 한 모델의 네 조건을 비교하는 동안 모델과 추론 설정은 바꾸지 않습니다.

지정 이미지를 처음 첨부하거나 불러오는 동작만 허용합니다. 그 뒤에는 추가 파일 읽기, 확대, 자르기, 리사이즈, OCR, 코드 실행과 외부 검색을 사용하지 않습니다. 답변에는 네 평가 항목만 남기고 확인 과정에 대한 설명은 요구하지 않습니다.

## 기준 답안과 채점 규칙

원본 도면에서 사람이 확인한 기준 답안은 다음과 같습니다.

| 평가 항목 | 기준 답안 |
|---|---|
| Reception Bin 2 장비 태그 | `11520-M-SI-04` |
| A측 하부 출구 밸브 | `V186` |
| Vibro Feeder #C 장비 태그 | Unit 1과 Unit 2 모두 `11520-M-VB-03C` |
| Feeder #C 바로 옆 전동기 | 원 안의 `EM`, 태그 `11520-E-MT-18` |

문자와 숫자가 기준 답안과 일치하면 항목당 1점입니다. 도면 글자 간격 때문에 Feeder 태그가 `11520 M-VB-03C`로 전사된 경우는 표준 태그 `11520-M-VB-03C`와 같은 값으로 정규화합니다. 그 밖의 문자나 숫자가 다르면 오답입니다. Unit 1과 Unit 2 가운데 하나라도 다르면 Feeder 항목은 0점이고, 전동기 심벌과 태그 가운데 하나라도 다르면 전동기 항목은 0점입니다. 읽지 못해 `확인하지 못함`으로 보류한 경우도 해당 항목은 0점입니다.

## 실험 1: 전체 이미지와 짧은 질문

`실습자료/이미지/전체-도면.png`를 새 대화에 첨부합니다. 도면의 전체 구조는 보이지만 작은 태그가 화면에서 차지하는 비율은 매우 낮습니다.

### 실험 1에 사용할 복사용 프롬프트

아래 프롬프트 전체를 복사해 입력합니다.

```text
이 P&ID에서 RECEPTION BIN 2의 A측 하부 출구에 있는 VIBRO FEEDER #C를 찾아 주세요.

도면에 직접 표시된 다음 네 항목만 그대로 적어 주세요.

1. RECEPTION BIN 2의 장비 태그
2. A측 하부 출구의 밸브 번호
3. VIBRO FEEDER #C의 장비 태그
4. Feeder #C 바로 옆 전동기의 심벌 표기와 태그

문자, 숫자와 하이픈을 보이는 그대로 옮겨 적으세요. Unit 1과 Unit 2의 Feeder #C 태그는 각각 확인하세요. 이미지에서 확인되지 않는 값은 추측하지 말고 `확인하지 못함`으로 적으세요.

지정된 이미지를 최초 입력으로 불러오는 기본 파일 읽기만 허용합니다. 이미지를 불러온 뒤에는 추가 파일 읽기, 외부 검색, 코드 실행, 줌·확대·자르기·리사이즈, OCR 등 추가 도구를 사용하지 말고, 제공된 이미지의 현재 해상도에서 한 번에 답변해 주세요.
답변은 `항목 | 판독값` 형식의 표 하나만 작성하고, 확인 과정은 설명하지 마세요.
```

기록된 실행에서는 Sonnet 3/4, Luna 2/4, Terra 2/4였습니다. 세 모델 모두 Bin 태그와 `V186`은 읽었지만, 작은 전동기 표기 또는 Feeder 태그에서 오류가 생겼습니다.

## 실험 2: 전체 이미지와 단계별 질문

이미지는 실험 1과 같은 `실습자료/이미지/전체-도면.png`입니다. 새 대화를 열고, 이번에는 확인 위치와 순서를 더 자세히 적은 프롬프트를 사용합니다.

### 실험 2에 사용할 복사용 프롬프트

```text
이 P&ID에서 RECEPTION BIN 2의 A측 하부 출구에 있는 VIBRO FEEDER #C를 다음 순서로 확인해 주세요.

1. `RECEPTION BIN 2`를 찾고 바로 아래에 적힌 장비 태그를 그대로 읽습니다.
2. Bin 하부의 `A` 표시 아래에 적힌 밸브 번호를 읽습니다.
3. `VIBRO FEEDER #C`를 찾고, Unit 1과 Unit 2 표기 옆의 장비 태그를 각각 그대로 읽습니다.
4. Feeder #C 바로 옆의 원형 전동기 심벌 안 글자와 그 아래 전동기 태그를 읽습니다.
5. 오른쪽의 다른 Feeder와 전동기 태그를 Feeder #C의 값으로 섞지 않습니다.
6. 문자, 숫자와 하이픈을 보이는 그대로 옮겨 적습니다.
7. 읽히지 않는 문자는 추측하지 않고 `확인하지 못함`으로 적습니다.

마지막에는 `항목 | 판독값` 형식의 표 하나만 작성하고, 확인 과정은 설명하지 마세요.

지정된 이미지를 최초 입력으로 불러오는 기본 파일 읽기만 허용합니다. 이미지를 불러온 뒤에는 추가 파일 읽기, 외부 검색, 코드 실행, 줌·확대·자르기·리사이즈, OCR 등 추가 도구를 사용하지 말고, 제공된 이미지의 현재 해상도에서 한 번에 답변해 주세요.
```

기록된 실행에서는 Sonnet 1/4, Luna 2/4, Terra 2/4였습니다. 세 모델 가운데 점수가 오른 모델은 없었습니다. 확인 순서를 자세히 알려 주어도 축소된 이미지 속 문자가 더 선명해지지는 않았습니다.

## 네 조건의 결과를 비교합니다

2026년 9월 4일, 각 조건을 새 일회성 세션에서 한 번씩 실행한 결과입니다.

| 모델 | 전체+짧은 질문 | 전체+단계별 질문 | 확대+짧은 질문 | 확대+단계별 질문 |
|---|---:|---:|---:|---:|
| Claude Sonnet | 3/4 | 1/4 | 4/4 | 4/4 |
| Codex Luna | 2/4 | 2/4 | 4/4 | 4/4 |
| Codex Terra | 2/4 | 2/4 | 4/4 | 4/4 |

Codex 8개 실행의 이벤트 로그에서는 추가 도구 호출이 기록되지 않았습니다. Claude 4개 실행의 최종 JSON에는 허용된 `Read` 호출 횟수가 남지 않아, 권한 거부와 서버 웹 도구 호출이 없었다는 점까지만 확인했습니다. 기존 제한 강화 전 기록은 `baseline/`에 보존하되, 위 표와 본문 해석에는 현재 `strict/` 결과만 사용합니다.

이 결과에서 직접 관찰한 내용은 다음 두 가지입니다.

- 전체 이미지에서는 단계별 프롬프트로 바꿔도 세 모델의 점수가 오르지 않았습니다.
- 확대 이미지에서는 짧은 프롬프트와 단계별 프롬프트 모두 세 모델이 네 항목을 읽었습니다.

따라서 이번 한 번의 실행에서는 지시의 길이보다 **관심 영역의 상대적 크기와 작은 글자의 가독성**이 판독 결과에 더 직접적인 영향을 보였습니다. 이 결과를 모델의 일반적인 성공률로 해석하려면 각 셀을 여러 번 반복하고 평균과 변동 범위를 함께 기록해야 합니다.

## CLI로 같은 조건을 실행하려면

데스크톱 앱에서는 각 섹션의 이미지와 프롬프트를 직접 사용하면 됩니다. CLI에서 한 조건만 실행하고 결과 파일을 남기려면 다음 형식을 사용합니다.

```bash
./scripts/run-workbook-cli.sh <도구> <조건>
```

| 값 | 선택지 |
|---|---|
| `<도구>` | `claude`, `codex-luna`, `codex-terra` |
| `<조건>` | `full`, `full-guided`, `zoom`, `zoom-guided` |

예를 들어 Luna에서 확대 이미지와 짧은 질문을 실행하려면 다음 명령을 사용합니다.

```bash
./scripts/run-workbook-cli.sh codex-luna zoom
```
